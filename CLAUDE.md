# sha256-learn

Материал для статьи: как из обратимых операций получается необратимая задача
(найти по хешу хоть какое-то сообщение).

## Главное правило: самое простое, что только возможно

- Если что-то можно упростить — упрощаем. Из двух вариантов берём более простой
  (например, квадрат вместо куба), даже если более сложный «аккуратнее».
- Числа — самые маленькие из возможных, при которых ещё сохраняется суть.
  Чтобы всё можно было проверить вручную.
- Один шаг — один файл: `src/step1.ts`, `src/step2.ts`, … (N в имени = число шагов хеша).
  Шаги хеша не пишем циклом — копируем строками.
- Общий алгоритм обращения (поиск корня многочлена) — в `src/algebra.ts`, шаги 2–25 импортируют только его.
  В шаге остаётся то, что относится к шагу: hash и какой многочлен решаем.
- Одно P в шагах 1–25: 786433 (простое, чуть меньше 2²⁰). Исключение — шаг 128: P = 2¹²⁸ − 159
  (простое в 16 байт), считается в BigInt, обратная не считается (сразу ошибка «infeasible»).
- Тесты — рядом: `src/stepN.test.ts`, встроенный `node:test`. Запуск: `node --test`.
- Страница: `index.html` + `src/page.ts` + `src/worker.ts`, сервер `node server.ts` — без зависимостей
  и сборки (Node сам убирает типы из .ts). Шаги о странице не знают; единственная уступка —
  необязательный параметр `progress` у долгих `invert`.
- Сборка: `./build.sh` → один файл `dist/index.html`, открывается двойным кликом (без зависимостей).
  Код фонового потока вклеен в страницу и запускается через Blob — иначе из file:// поток не стартует.
- Ничего лишнего: никаких новых файлов, сборки и вариантов «для сравнения», пока об этом не попросили.
